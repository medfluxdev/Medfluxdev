# مدفلكس (Medflux) — المشغّل المحلي (Local Launcher)

> نظام تحليل وتتبع عقود الصيانة والخدمات للمستشفيات الألمانية، يعمل محليًا بالكامل
> دون أي اتصال خارجي أو اشتراك سحابي للذكاء الاصطناعي.

يُتيح هذا المشغّل تشغيل النظام كاملًا على الجهاز المحلي مع اختيار نموذج الذكاء
الاصطناعي المثبّت محليًا فقط، وعدم تحميل أي نموذج من الإنترنت نهائيًا.

---

## 1) المتطلبات الأساسية (قبل التشغيل)

العناصر التالية يجب أن تكون موجودة ومهيّأة على الجهاز قبل استخدام المشغّل:

| العنصر | الحالة المطلوبة | ملاحظات |
|--------|-----------------|---------|
| قواعد البيانات PostgreSQL | تعمل على `127.0.0.1:5432` أو عبر Docker | المشغّل يستخدم نفس سكربت المشروع (`scripts/start_local_postgres.ps1`) |
| Ollama | **يجب تشغيله يدويًا أولًا** | لا يقوم المشغّل بتشغيله أو إيقافه أبدًا |
| نموذج ذكاء محلي واحد على الأقل | مثبّت داخل Ollama | لا يقوم المشغّل بتحميل أي نموذج |
| المكوّنات الخلفية (Backend) | مجلد `backend\.venv` جاهز | تثبيت مسبق بنفس بيئة المشروع |
| الواجهة الأمامية (Frontend) | مجلد `frontend\node_modules` جاهز | تشغيل `npm install` مرة واحدة يدويًا |

> **تحذير أمني مهم:** لا يعدّل المشغّل أي ملف `.env` ولا أي إعداد أمان أو
> مصادقة (Authentication/TLS)؛ ولا يثبّت برامج، ولا يغيّر إعدادات قاعدة
> البيانات نهائيًا.

---

## 2) تشغيل النظام خطوة بخطوة

1. **شغّل Ollama يدويًا** إن لم يكن يعمل (الخدمة على المنفذ `11434`):
   ```bash
   ollama serve
   ```
2. **تأكد من وجود نموذج محلي واحد على الأقل**:
   ```bash
   ollama list
   ```
   إن لم يوجد نموذج، ثبّته يدويًا (هذه هي الطريقة الوحيدة المسموحة لتحميل النماذج):
   ```bash
   ollama pull qwen3-vl:8b-instruct
   ```
3. **انقر نقرًا مزدوجًا على ملف** `START_MEDFLUX_LOCAL.bat`.
4. سيقوم المشغّل تلقائيًا بما يلي:
   - فحص/تشغيل PostgreSQL (عبر سكربت المشروع نفسه).
   - التأكد أن Ollama يعمل.
   - عرض قائمة بالنماذج المثبتة محليًا مع تمييز النماذج القادرة على تحليل الصور.
   - **اختر رقم النموذج المطلوب** ثم اضغط Enter.
     - لاحظ الوسم `[VISION]` = نموذج يدعم تحليل المستندات الممسوحة ضوئيًا
       (PDF/صور)، والوسم `[text]` = نموذج نصي فقط.
     - اضغط Enter بدون رقم للإبقاء على الاختيار الحالي، أو `0` لعدم تغيير شيء.
   - ضبط Medflux لاستخدام النموذج المحلي المختار (يُثبَّت المزوّد على `ollama` محليًا دائمًا).
   - تشغيل الواجهة الخلفية `http://localhost:8000` والواجهة الأمامية `http://localhost:3000`.
5. سيُفتح المتصفح تلقائيًا على صفحة النظام.

## 3) عنوان الوصول بعد التشغيل

| الواجهة | العنوان |
|---------|---------|
| التطبيق (الواجهة الأمامية) | `http://localhost:3000` |
| الواجهة الخلفية (API) | `http://localhost:8000` |
| خادم الذكاء المحلي (Ollama) | `http://127.0.0.1:11434` |

---

## 4) إيقاف التشغيل بأمان

انقر نقرًا مزدوجًا على ملف **`STOP_MEDFLUX_LOCAL.bat`**.

يقوم بإيقاف **العمليات التي بدأها المشغّل فقط** (الواجهة الخلفية والواجهة
الأمامية) بناءً على معرّفات العمليات (PIDs) المسجّلة، ويستبعد التحقق من سطر
أوامر العملية لكل منها لضمان عدم إيقاف أي عملية غير تابعة للمشغّل.

**لا يلمس المشغّل إطلاقًا:**
- Ollama الذي كان يعمل قبل التشغيل (يظل قائمًا كما هو).
- PostgreSQL (يظل يعمل؛ يمكن إيقافه لاحقًا بأدواته الخاصة).

> إن أردت إيقاف كل شيء تمامًا، فأوقف Ollama وPostgreSQL يدويًا بأدواتهما.

---

## 5) الضمانات المحلية (ولماذا هي آمنة)

- **لا تحميل للنماذج:** المشغّل يستدعي `ollama pull` أبدًا؛ يستعرض النماذج
  المثبتة فقط (`/api/tags`) ويطلب رقم النموذج المثبّت.
- **لا سحابة:** المزوّد مثبّت على `ollama` المحلي فقط، ولا يوجد أي مزوّد سحابي
  أو نقطة نهاية خارجية.
- **لا كتابة على ملفات `.env`** ولا تعديل متغيرات بيئة النظام.
- **المصادقة وTLS وقواعد الأمان** تبقى كما هي دون تغيير.
- **الخصوصية:** لا تُرسَل بيانات العقود خارج الجهاز؛ ولا تُستدعى واجهات
  ذكاء خارجية.
- **حلول آمنة عند الفشل (fail-closed):** إن لم يوجد نموذج أو لم يكن Ollama
  يعمل، يتوقف المشغّل برسالة واضحة بدلًا من المتابعة بعشوائية.
- **تحقق الهوية قبل نجاح PostgreSQL:** لا يكتفي المشغّل بمنفذ TCP مفتوح؛ بل
  يختبر بروتوكول PostgreSQL الفعلي عبر رسالة بدء تشغيل قبل أن يعلن جاهزيته.
  أي خدمة أخرى على نفس المنفذ لا تُعدّ قاعدة بيانات (تصحيح "منفذ يستمع ≠
  قاعدة بيانات".

## 6) استكشاف الأخطاء

| العَرَض | السبب / الحل |
|---------|--------------|
| "Ollama is not running on ..." | شغّل `ollama serve` أو تطبيق Ollama ثم أعد التشغيل. |
| "No local models installed" | ثبّت نموذجًا يدويًا: `ollama pull qwen3-vl:8b-instruct`. |
| "frontend\node_modules is missing" | نفّذ `npm install` داخل مجلد `frontend` مرة واحدة. |
| "Backend did not become ready" | راجع السجل: `%LOCALAPPDATA%\MedFlux\runtime\backend.log`. |
| "Frontend did not become ready" | راجع السجل: `%LOCALAPPDATA%\MedFlux\runtime\frontend.log`. |
| النموذج المُختار بلا وسم `[VISION]` | لا يمكن تحليل المستندات الممسوحة ضوئيًا؛ اختر نموذج Vision. |
| رسالة اختيار من Medflux UI | حدّد النموذج مرة واحدة داخل واجهة النظام ثم أعد التحليل. |

## 7) الملفات المساعدة

| الملف | الوظيفة |
|-------|---------|
| `START_MEDFLUX_LOCAL.bat` | المشغّل الرئيسي (تشغيل واختيار نموذج). |
| `STOP_MEDFLUX_LOCAL.bat` | الإيقاف الآمن للعمليات التي بدأها المشغّل. |
| `scripts/ollama_models.ps1` | استكشاف النماذج المثبتة وتحديد قدرة الرؤية. |
| `scripts/set_local_model.py` | تثبيت اختيار النموذج داخل Medflux (المزوّد `ollama` فقط). |
| `scripts/spawn_medflux_backend.ps1` | تشغيل الواجهة الخلفية مع تسجيل الصنف PID. |
| `scripts/spawn_medflux_frontend.ps1` | تشغيل الواجهة الأمامية مع تسجيل الصنف PID. |
| `scripts/stop_medflux_runtime.ps1` | إيقاف العمليات المسجلة فقط بعد التحقق الآمن. |
| `scripts/start_local_postgres.ps1` | سكربت PostgreSQL الموجود أصلًا في المشروع (يُعاد استخدامه). |

---

## 8) ملاحظة أخيرة

يعمل النظام محليًا بالكامل ولا يحتاج سوى وجود Ollama ونموذج نصي واحد
(ويُفضَّل نموذج داعم للرؤية مثل `qwen3-vl:8b-instruct` لتحليل بوالص PDF
الممسوحة ضوئيًا أو المتضمنة صورًا).
